# Meeseeks Factory для BB

Фабрика софта для портфеля новых и существующих продуктов: общий обзор личных и рабочих проектов, ручной РНП, рабочие разделы методологии Mr Meeseeks и редактируемый пакет правил с фиксацией версий.

## Реализовано

- Страница «Фабрика софта» в боковой панели BB с главным обзором портфеля.
- Личные и рабочие проекты, фильтры и поиск; цель, ручная оценка состояния, следующий шаг и блокер.
- РНП («рука на пульсе»): цель, состояние, блокер и следующий шаг проекта; неизвестные данные остаются неизвестными.
- Первичный разбор проекта отдельной агентской задачей BB по явному нажатию кнопки; добавление черновиков с источниками без перезаписи прежних записей.
- Рабочее пространство каждого проекта: 23 раздела — от паспорта, аудитории и джоб до инициатив, задач, срезов, ТЗ и приёмки, плюс решения и открытые вопросы.
- Структурированные карточки записей и связи в пределах проекта; ручное редактирование с проверкой версии, журнал и защита входящих связей от удаления.
- История версий артефактов: неизменяемые снимки до и после правки, просмотр прошлых полей, связей и ручного статуса без изменения текущей записи.
- Каталог существующих продуктов из `~/Desktop/Проекты разработка`: поиск, страницы и выбор с заполнением имени и канонического пути.
- Создание нового проекта и подключение существующего продукта с репозиторием и ручным описанием исходного состояния.
- Редактируемая карточка с защитой от устаревшего сохранения, стадия перехода и закреплённая версия методологии для каждого проекта.
- Локальный снимок всех 21 скилла Mr Meeseeks: 51 исходный файл, включая скрипты и инструкции вложенных агентов. SHA256 каждого файла — в `methodology/manifest.json`.
- Просмотр всех файлов в интерфейсе; редактирование текущей версии создаёт неизменяемую ревизию. Исторические версии доступны для чтения.
- Явный перевод выбранного проекта на другую версию. Правка пакета не меняет версии проектов.
- Защита от сохранения устаревшей версии и сериализация конкурентных записей внутри экземпляра плагина.
- CLI для агентов и operating skill без автоматической инъекции всего пакета в каждый тред.

## Запуск

```sh
pnpm install --ignore-workspace --frozen-lockfile
pnpm run typecheck
pnpm test
bb plugin build
bb plugin install .
```

Этот плагин не входит в текущий pnpm workspace монорепозитория, поэтому команды выполняются непосредственно из его каталога. Для изолированной установки можно передать `--store-dir` с отдельным временным каталогом.

Пункт интерфейса BB: «Фабрика софта». Плагин использует `@get-bb/plugin-sdk` 0.6.104, React/TypeScript и хранилище BB. Статус и путь работающей установки показывает `bb plugin source meeseeks-factory --json`. Данные плагина хранятся отдельно от каталога исходников и привязаны к его ID.

## Команды

```sh
bb meeseeks-factory projects list --limit 20 --offset 0
bb meeseeks-factory projects discover --query loocl --limit 20 --offset 0
bb meeseeks-factory projects show <id>
bb meeseeks-factory projects create '{"name":"Продукт","mode":"existing","repository":"/path/to/repo","baseline":"Текущее состояние"}'
bb meeseeks-factory methodology info
```

Список возвращает не более 20 карточек за запрос; страницы доступны через `--offset` и кнопки интерфейса.

Для mode=`existing` репозиторий и baseline обязательны; для mode=`new` они могут быть пустыми строками. Путь репозитория сохраняется как контекст и не открывается автоматически.

## Подключение существующего продукта

В форме выберите «Существующий продукт», найдите каталог и выберите его из списка. Имя и канонический путь заполнятся автоматически, исходное состояние заполняется вручную. Кнопка «Обновить список» перечитывает каталог; поиск работает по имени и пути во всём каталоге, а не только на первой странице. Через «Указать путь или URL вручную» можно подключить репозиторий вне каталога или продолжить при недоступном источнике.

Источник — `os.homedir()/Desktop/Проекты разработка` на машине сервера BB. Корень может быть символической ссылкой. Плагин читает только непосредственные каталоги и метаданные ссылок, исключает скрытые имена, обычные файлы и ссылки на файлы, объединяет ссылки на один канонический каталог. Повреждённые ссылки пропускаются с предупреждением. Содержимое проектов, `.env` и другие файлы не открываются. Сканирование не создаёт карточки фабрики и проекты BB автоматически.

В локальном прототипе доступна файловая система сервера; discovery не перечисляет каталоги удалённого хоста/компьютера браузера. При недоступном источнике ошибка отображается в выборе каталога; существующие карточки продолжают работать. RPC `projects_discover` и CLI `projects discover` возвращают максимум 20 записей, root, canonicalRoot, total, offset, limit и ограниченный список предупреждений.

## Рабочий контур и РНП

Главная страница — обзор портфеля подключённых проектов. «Открыть проект» ведёт внутрь выбранного продукта; после создания карточки рабочее пространство открывается сразу. Форма подключения находится в «Каталог и настройки» и свёрнута при наличии проектов.

### Нативный флоу в BB

Обзор портфеля → «Открыть проект» → «Начать разбор» → обычный тред агента BB. Дальше отвечайте и уточняйте решения в том же треде; агент ведёт первичный разбор и добавляет черновики с источниками. В рабочем пространстве появляется основная кнопка «Продолжить в треде». Формы разделов нужны для просмотра и правок, их заполнение не является обязательным первым шагом.

Только в тредах, созданных фабрикой, нативная карточка контекста BB показывает проект, цель, состояние разбора и закреплённую версию правил. Нажатие на название открывает именно этот проект фабрики через штатную навигацию BB. В режиме banner и на мобильном вместо карточки появляется компактная ссылка «Фабрика · проект»; одновременно два представления не показываются. В посторонних тредах фабрика не появляется.

Этот нативный флоу относится к первичному разбору. Полная реализация инициативы, доставка и автоматическая приёмка пока остаются отдельным этапом.

### С чего начать заполнение

В рабочем пространстве нажмите «Начать разбор проекта». Для запуска в карточке должен быть указан абсолютный путь к существующему локальному репозиторию; пустое значение и URL без локального checkout не подходят. Плагин создаёт обычную агентскую задачу в соответствующем проекте BB; задачу можно открыть из панели запуска. Нажатие не подтверждает будущие продуктовые решения.

Разбор собирает подтверждённый контекст из кода и документов и добавляет черновики со ссылками на источники. Джобы и инициативы не придумываются при отсутствии оснований; неизвестное остаётся вопросами. Существующие записи не перезаписываются. Когда черновики импортированы, панель показывает ссылки на них, а счётчики рабочего пространства обновляются. Проверьте исходные материалы и отредактируйте или подтвердите записи вручную.

При выполняющемся запуске новый разбор заблокирован. Если другой клиент уже успел запустить разбор, сервер сохраняет связь requestId с существующей задачей, а интерфейс принимает именно эту подтверждённую связь. Проверка `analysis_lookup` может записать такую связь, но сама не запускает агента. Один лишь чужой activeRun без подтверждения связанного requestId не очищает ожидающий идентификатор. После неясного сетевого исхода отдельная проверка по идентификатору запроса выясняет, был ли он принят; автоматического повторного запуска нет. Отсутствие записи пока не доказывает, что исходный запрос не придёт позже. Панель сохраняет requestId в sessionStorage именно этого проекта до отправки и предлагает «Повторить тот же запрос» с тем же UUID. Новый UUID не создаётся по отсутствию записи; новое нажатие после подтверждённого завершения или безопасного закрытия — отдельный запуск.

Остановка хода агента без импорта переводит запуск в «Агент остановился; результат не импортирован». Из этого состояния можно продолжить задачу агента в чате либо нажать «Закрыть запуск без результата». Сервер повторно проверяет, что задача не выполняется, и только после безопасного закрытия разрешается новый разбор. Закрытие не удаляет записи проекта. Само завершение хода агента не переводит разбор в готовое состояние.

 Если состояние неизвестно, панель предлагает проверить существующую задачу и не отправляет повторный запрос. Кнопка повтора доступна для запуска с подтверждённым состоянием ошибки. Первичный разбор не запускает автоматически полный цикл реализации и приёмки.

В проекте постоянно доступны разделы «Замысел и потребности», «Решения и устройство», «Работы и приёмка», «Журнал». Паспорт показывает исходный контекст карточки; отдельные поля паспорта заполняются вручную. Можно создать джобу, затем инициативу со связью на неё, далее задачи и остальные артефакты. Цели связей выбираются только из записей своего проекта, поиск и список поддерживают страницы. Пока ответ для текущего раздела или поиска ещё не получен, интерфейс показывает загрузку; счётчики обозначаются «…». Пустое состояние появляется только после успешного ответа именно на текущий запрос, поэтому данные прежнего раздела не выдаются за новый результат. Пустые уровни не заполняются вымышленными данными; применимость необязательных уровней определяется методологией. Для технической инициативы отсутствие джобы допустимо.

Каждая запись сохраняется как черновик. «Подтверждено вручную» — отметка заполнения, которая не означает автоматическую проверку скиллами, успешные тесты, мерж PR или достижение продуктовой цели. При конфликте редактирования пользовательский текст остаётся в форме. «История изменений» показывает сохранённые версии с датой и номером; просмотр только для чтения и не подменяет текущий редактор. Для записей, созданных до появления истории, исходное состояние фиксируется при первой последующей правке. Текущий адаптер формы не исполняет правила Markdown; кнопка правил раздела открывает файл из закреплённой версии пакета.

«Обновить РНП» редактирует принадлежность (личный/рабочий/не распределён), цель, состояние (не оценено/по плану/риск/блокировка), следующий шаг и блокер. Эти значения задаются вручную. Изменение РНП через интерфейс не отправляет и не перезаписывает скрытые числовые метрики. Счётчики джоб и задач показывают объём реестра и не используются для вывода об успехе продукта. Числовые показатели в интерфейс этой версии не включены; автоматическое вычисление состояния пока не подключено.

Записи рабочего контура и РНП хранятся в SQLite плагина с транзакциями, проверкой версии и изоляцией проектов. Карточки проектов и версии пакета используют прежнее KV-хранилище. Ранее созданные проекты открываются без удаления и повторного подключения; пустой рабочий контур не меняет их данные.

## Версии и данные

Исходные файлы лежат в `methodology/meeseeks-*/`. `bundle.json` содержит их полный импорт для включения в серверную сборку: после сборки нет зависимости от абсолютных путей первоначального каталога. `manifest.json` хранит SHA256 файлов. Пакет импортирован из локальной установленной коллекции; официальный upstream пока неизвестен.

При первом запуске файлы записываются в KV как отдельные блобы по SHA256, ревизия — отдельный манифест. Проекты хранятся отдельными объектами. Один объект ограничен 240 КБ JSON, исходный файл — 120 КБ UTF-8, максимум 500 проектов и 200 ревизий. Данные переживают reload. После первого импорта существующая head сохраняется при перезагрузке: замена bundle сама по себе не перезаписывает локальную историю.

Редактор принимает expectedRevision. Если текущая head уже изменилась, сохранение отклоняется. Карточка использует expectedUpdatedAt. Создание новой версии сохраняет прежние файлы и pin каждого проекта. Пакетные обновления upstream и их слияние появятся отдельным этапом.

## Проверка

После обновления и reload 2026-11-02 реальная команда `projects discover` обнаружила 55 уникальных каталогов в `~/Desktop/Проекты разработка` (56 записей до объединения ссылок). Проверены первая и последняя страницы, а также поиск `solopreneuro`; ошибок каталога нет. Набор проверок включает discovery на временных каталогах. Проверка типов и сборка обновлённого плагина успешны.

`pnpm test` проверяет полный жизненный цикл карточки, изоляцию проектов, явную смену pin, неизменность исторических файлов, защиту от устаревшего сохранения, конкурентные записи, ограничения размера, проверку пути и повреждённых хешей. Mutation check подтверждён: отключение CAS, неверный pin, обход сериализации, отключение hash-проверки, снятие пагинации и игнорирование baseline update делают соответствующие тесты красными. Проверки запускаются вместе с остальными backend- и UI-тестами. Mutation check discovery также подтверждён для скрытых имён, canonical dedup и пагинации. Discovery дополнительно проверяется на временных каталогах: symlink корня/каталогов, скрытые файлы, повреждённые ссылки, canonical dedup, поиск, пагинация и ошибка корня. Тесты доменные, с изолированным KV в памяти; они не заменяют проверку UI внутри BB.

## Дальнейшая разработка

Ранние сценарии интерфейса проверены в живом BB: обзор, ручной РНП, рабочий контур проекта, связи и история. Для новых изменений нужны соответствующие повторные проверки.

[Спецификация фабрики](docs/factory/README.md) описывает целевой продукт и критерии следующих срезов. В этой версии ещё нет импорта внешнего бэклога и метрик, автоматического запуска полного цикла реализации и приёмки, upstream sync/three-way merge, полноценного восстановления после аварий между KV-записями и автоматической приёмки. Связи задач, срезов, ТЗ и PR заполняются вручную; совместимость локального реестра с официальными XLSX-схемами требует отдельного адаптера. Статус перехода — ручная отметка, не доказательство соответствия кода стандарту.

Транзакционное хранение рабочего контура уже используется; атомарность операций между ним и прежним KV требует доработки перед автоматическими миграциями реестров. Текущий прототип рассчитан на один сервер BB.

## Проверка нативной связи

`pnpm run test:ui` использует официальный fake-runtime SDK и jsdom: проверяет mapped/unmapped треды, режимы card/banner без дублирования, закреплённую версию запуска и SDK-переход к правильному factory projectId. Отдельный тест моделирует потерю ответа, отсутствие записи, remount, повтор с тем же UUID и новый UUID только после подтверждённой ошибки. Реальные агентские треды в этих тестах не создаются. `pnpm test` запускает и backend, и UI-проверки.
