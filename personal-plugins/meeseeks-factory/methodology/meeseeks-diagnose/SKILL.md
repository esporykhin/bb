# Meeseeks Diagnose - разбор падения по дампу

Выполняется здесь, в Codex Desktop. Вход - дамп `mrctl dump`. Выход - отчёт из двух частей:
спасение и заключение.

Дамп самодостаточен по построению. Ответ «надо посмотреть лог на сервере» недоступен: чего нет
в дампе, того в разборе нет. Недостающее называется как недостающее, а не достраивается
догадкой.

## Что уже названо воркером

`worker.sh` классифицирует отказ сам и пишет код возврата и пометку в `history.log`. Дамп
кладёт их в первые строки секции `## признаки`. Эти классы не переоткрываются.

| rc | что произошло |
|---|---|
| 90 | `setup-failed` - окружение не собралось, агент не запускался |
| 91 | `git-failed` - fetch или worktree |
| 92 | `orphaned` - воркер перезапустили посреди прогона |
| 93 | `verify-failed` - окружение собралось, но `VERIFY_CMD` не прошёл |
| 94 | `precondition-missing`, `halt-*`, `no-output` |
| 95 | `gate-broken-before`, `gate-regression` |
| 96 | `managed-git-failed`, `push-failed` |
| 124 | таймаут задачи |
| 1 | отказ клиента: бюджет, сбой шлюза, прочее |

Пометки поверх кода: `budget-exhausted`, `permission-denied-N`, `resumed-N`,
`resume-failed-N`, `resumed-budget-N`, `salvaged`, `pushed-unsent`, `unsent-bundle`,
`already-done`, `api-retry-N/M`, `api-retries-exhausted`, `fix-failed-N`, `cache-N%`.

Пометка называет симптом, не причину: она говорит, что произошло, и ничего не говорит о том,
почему. Работа скила начинается здесь.

Пометка `no-output` означает «прогон не произвёл результата» - о причине в ней нет ничего.

## Порядок чтения дампа

1. `## признаки` - целиком, до всего остального. Отсюда версия происходящего.
2. `worker_diff` - если `True`, установленный `worker.sh` разошёлся с репозиторием, и
   поведение воркера не выводится из кода в master. Это называется первым пунктом заключения,
   потому что подрывает любой другой вывод.
3. Пометка `note` - и сразу секция, которая её подтверждает или опровергает (таблица ниже).
4. `## промпт` - что реально ушло модели. Не файл ТЗ из inbox: постскриптум дописывает воркер.
5. Остальные секции - по необходимости, а не подряд.

Секция с телом `(нет)` означает отсутствие данных, а не отсутствие секции.

## Отчёт агента доверия не имеет

Секция `## результат`, поле `result` - это то, что агент написал о себе. Оно сверяется с
секциями `## setup` и `## гейты`, а не принимается. Расхождение вида «все тесты прошли» при
сломанном гейте - отдельная находка, а не мелочь: она означает, что агент завершился по
`end_turn`, не проверив дерево, которое закоммитил.

Признаки такого расхождения: `stop_reason` = `end_turn` и `is_error` = false при ненулевом
`rc`; перечень галочек по приёмочным критериям; заявленное число пройденных тестов при
ошибке сборки в гейте. Язык итога, отличный от языка ТЗ, - сопутствующий признак сноса
инструкции, отмечать отдельной строкой.

## Симптом → чем подтверждается в дампе

| Признак или пометка | Что это обычно | Чем подтверждается |
|---|---|---|
| `tool_calls` = 0 | промпт не доехал до модели, сгоревший старт | `## таймлайн` пуст, `turns` = 1; воркер уже ставит задачу на повтор сам |
| `no-output`, `tool_calls` > 0 | поток оборвался на границе вызова инструмента | `## git`: коммиты или грязное дерево есть, в origin их нет |
| `halt-needs-decision` | ТЗ не делает выбора, который нужен для работы | `## результат`: строка `MEESEEKS-HALT`; адресат - ТЗ |
| `halt-precondition` / `precondition-missing` | встала предыдущая часть цепочки | `## setup`: имя недостающей части; разбирать надо её, не эту |
| `turns` близко к `max_turns` | ТЗ не помещается в потолок исполнения | `## таймлайн` ровный, без повторов - работа шла и не кончилась |
| `budget-exhausted` при ровном таймлайне | то же: объём, а не сбой | `cost_usd` ≈ `max_budget`, `## повторы` пуст |
| `budget-exhausted` при непустых `## повторы` | зацикливание: агент повторяет одно и то же | группа из трёх и более одинаковых вызовов |
| `permission-denied-N` | режим `dontAsk` отверг инструмент, агент перебирал формулировки | `## повторы` плюс счётчик; чинится в настройках Codex, не в env очереди |
| `setup-failed` | окружение | `## setup`: команда и её вывод; частые причины - приватный индекс пакетов и права |
| `verify-failed` при `setup_skipped` = True | отпечаток зависимостей совпал, а окружение битое | `## setup`: строка про пропуск setup |
| `gate-regression` | гейт ухудшился после правки | `## гейты`: направление и ключи; отличать регрессию кода от окружения гейта |
| `gate-regression` целиком в новых файлах | код писался без прогона линтера | `## гейты`, блок «Появилось»: все ключи в файлах, созданных этим прогоном |
| гейт «перестал запускаться» | это не регрессия, а поломка: сборка тестов не проходит | `## гейты`: `ImportError`, `Interrupted: N error during collection` |
| `fix-failed-N` | фикс-агент не справился | сверить объём регрессии с потолком фикс-агента в `## setup`, строка «потолок» |
| `gate-broken-before` | гейт был красным до агента | прогон не при чём, чинить надо предыдущее состояние ветки |
| `api-retries-exhausted` | шлюз, а не задача | одинаковый обрыв во всех попытках секции `## запуск` |
| `push-failed` | ветка, права или разошедшаяся история | `## setup`: вывод push; `## git`: расхождение с origin |
| гейт прогона против снимка контракта красный, а затронутый код прогон не менял | расхождение со снимком: изменилась вторая сторона | `## гейты`: ключи в проверке снимка; `## git`: диффа в этих файлах нет; адресат - `КОНТРАКТ`, не `ТЗ` и не `СРЕДА` |
| низкий `cache-N%` | дорого, но не причина падения | в заключение идёт отдельной строкой, с причиной не смешивается |

Совпадение симптома с таблицей - гипотеза, которую подтверждает секция дампа. Не подтвердилась
- так и пишется, вместо подстановки самого правдоподобного объяснения.

## Три взгляда

Разбор ведётся по трём вопросам, они не смешиваются.

**Задача.** Было ли ТЗ исполнимым в том виде, в котором ушло модели? Смотреть `## промпт`:
противоречия, ссылки на файлы и цели, которых нет, объём сверх потолка, выбор, который ТЗ не
делает, предусловие части. Отказ такого рода воспроизведётся на любом прогоне, и чинить его
повтором бессмысленно.

**Прогон.** Что случилось именно в этот раз? Обрыв потока, шлюз, потолок бюджета, права,
окружение. Отличается от предыдущего тем, что тот же промпт на следующем прогоне проходит.

**Система.** Что допускает повторение? Здесь ответ ищется не в этом прогоне, а в том, чем он
похож на другие. Источник - секция `## запуск` с перечнем попыток задачи. Одного дампа для
системного вывода мало; если данных нет, так и сказать и назвать, что нужно посмотреть -
`mrctl ls --status failed`, второй дамп, распределение пометок за неделю.

Смешение взглядов - частая ошибка разбора: «упало из-за сбоя шлюза» закрывает вопрос прогона и
оставляет открытым вопрос системы - почему исчерпались три попытки и почему это не заметили.

## Часть 1 - Спасение

Идёт первой в отчёте, потому что срочная. Дерево упавшей задачи убирается по лимиту
`WT_KEEP_LAST`, то есть счёт идёт на три следующих прогона очереди, а не на дни.

Работа лежит в одном из четырёх мест, от безопасного к исчезающему:

1. коммит в origin - делать нечего;
2. локальные коммиты в worktree - исчезнут вместе с деревом;
3. патч `logs/<id>.salvage.patch` или бандл `logs/<id>.unsent.bundle` - живут, пока жив каталог логов;
4. незакоммиченные правки в дереве - исчезнут первыми.

Что где лежит, видно в секции `## git`, поле `где работа`, и в пометках `salvaged`,
`pushed-unsent`, `unsent-bundle` - они означают, что воркер уже спас работу сам.

Инструкция выдаётся командами, готовыми к запуску, с подставленным id. Первая всегда -
удержание, до любого разбирательства:

```
mrctl salvage <id> --keep        # поднять дерево в очереди на уборку
mrctl salvage <id>               # что именно осталось и где
mrctl salvage <id> --to ~/<id>.patch
mrctl salvage <id> --push        # довести до origin, если ветка уже там
```

Бандл возвращается иначе:

```
git fetch <путь к unsent.bundle> <ветка>:<ветка>
```

Если спасать нечего - так и пишется одной строкой, без набора команд «на всякий случай».
Ложная инструкция по спасению хуже её отсутствия: по ней человек второй раз коммитит то, что
давно в origin.

Границы: скил не запускает `mrctl salvage`, не пушит и не коммитит. Он выдаёт команды, которые
человек выполняет сам.

## Часть 2 - Заключение

Адресат правки - из фиксированного множества:

| Адресат | Когда |
|---|---|
| `ТЗ` | отказ воспроизведётся на любом прогоне: противоречие, недостающий выбор, объём сверх потолка |
| `ШАБЛОН` | процессная часть промпта, общая для всех задач очереди (см. `meeseeks-tdd-implementer`) |
| `КОНФИГ` | env очереди: `MAX_TURNS`, `MAX_BUDGET`, `SETUP_CMD`, `VERIFY_CMD`, `TASK_TIMEOUT`, гейты |
| `ВОРКЕР` | код `worker.sh`, `gates.sh`, `managed-git.sh`, `mrctl` |
| `КЛИЕНТ` | настройки Codex: разрешения инструментов, скилы |
| `КОНТРАКТ` | расхождение со снимком контракта: правка у держателя формы или у второй стороны |
| `СРЕДА` | шлюз, сеть, репозиторий, стенд |
| `ЛОЖНОЕ` | прогон годен, ошибочен критерий, по которому он признан упавшим |
| `НЕТ-ПРИЗНАКА` | адресата назвать нечем: в дампе не хватает данных |

`НЕТ-ПРИЗНАКА` - не отказ от ответа, а результат: он означает заявку на новый вычисляемый
признак в `mrctl dump` или новую пометку в `worker.sh`. Такой вывод формулируется как
конкретное поле, которого не хватило.

Каждый вывод несёт три части: адресат, изменение, проверка. Проверка - как узнать, что помогло:
какой признак в следующем дампе должен измениться и на что.

Повторяемость помечается одним из трёх: `разово`, `повторяемо`, `неизвестно`. Третье - штатное
значение при одном дампе, а не отговорка.

Действие - из множества: `retry как есть`, `retry после правки конфига`, `переписать ТЗ`,
`править воркер`, `ничего`.

Приоритет: `ЛОЖНОЕ` называется раньше всего остального - если прогон годен, чинить нечего.
`worker_diff` = True называется раньше любого вывода про поведение воркера.

## Границы полномочий

- Не правит код, не пишет патчи, не коммитит.
- Не ставит задачу в очередь и не запускает `mrctl`.
- Не выбирает за человека на развилке: два равновозможных объяснения - оба в отчёт, с тем, чем
  каждое подтверждается и чем различается.
- Не выдаёт правдоподобное за установленное. Формулировки «вероятно», «по имеющимся данным»
  используются там, где так и есть.
- Не переписывает ТЗ: заключение с адресатом `ТЗ` - вход для `meeseeks-fix-spec`, не замена ему.
- Не чинит контур: заключение с адресатом `ВОРКЕР`, `КОНФИГ`, `ШАБЛОН` или `КЛИЕНТ` - вход
  для `meeseeks-harden`. Это находка про устройство контура, и в бэклог предметного проекта
  она не заводится.

Если адресат - `ВОРКЕР`, код читается через GitHub MCP в репозитории воркера, а не
восстанавливается по памяти: файл на стенде и файл в master расходятся.

## Формат отчёта

```markdown
# Разбор прогона [id]

**Очередь:** [env] · **Задача:** [task] · **rc:** [N] · **Пометка:** [note]
**Ветка:** [branch] · **Попыток задачи:** [N]

## Спасение
[что и где осталось — одной строкой]
[команды по порядку, либо «спасать нечего: работа в origin»]
Срок: дерево убирается через [N] прогонов очереди по лимиту WT_KEEP_LAST.

## Что случилось
[одна фраза: причина, не симптом]

### Задача
[исполнимо ли ТЗ в том виде, в котором ушло модели]

### Прогон
[что случилось в этот раз; чем подтверждается — секция и строка дампа]

### Система
[повторяемо ли; на чём основан вывод; чего не хватает для системного вывода]

## Заключение

| Адресат | Изменение | Проверка | Повторяемость |
|---|---|---|---|
| [из множества] | [что конкретно править] | [какой признак изменится] | разово/повторяемо/неизвестно |

**Действие:** [из множества]

## Чего не хватило в дампе
[поля и секции, которых недоставало; пусто, если хватило всего]
```

## Сохранить и отдать

Файл `/mnt/user-data/outputs/Diagnose-[id прогона].md`, имя латиницей - карточка
`present_files` не отрисовывается для кириллицы в имени. Вызвать `present_files`. В чат
коротко: причина одной фразой, адресат, действие.

## Критические правила

- Вход - дамп. Нет дампа - скил не работает: догадка по номеру прогона хуже отсутствия ответа.
- Код возврата и пометка уже названы воркером; они не переоткрываются, а служат отправной точкой.
- Пометка - симптом. Причина называется отдельно и подтверждается секцией дампа.
- Спасение идёт первым: срок жизни дерева - три прогона очереди, не дни.
- Инструкция по спасению выдаётся только когда есть что спасать; иначе одна строка «нечего».
- Три взгляда не смешиваются: закрытый вопрос прогона не закрывает вопрос системы.
- Адресат - из фиксированного множества. `НЕТ-ПРИЗНАКА` - результат, а не отказ отвечать.
- Каждый вывод несёт проверку: какой признак в следующем дампе должен измениться.
- `worker_diff` = True называется раньше любого вывода о поведении воркера.
- Низкая доля кэша - строка про стоимость, не причина падения.
- Скил не правит, не пушит, не ставит в очередь и не выбирает за человека.
