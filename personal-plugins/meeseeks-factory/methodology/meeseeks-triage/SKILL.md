# Meeseeks Triage - быстрый триаж среза по ID

## Единица триажа

Единица триажа - срез, не задача. Граница среза и правило поставки - см. `meeseeks-slice`
(`граница-среза`). ТЗ среза может быть разрезано на упорядоченные части, все они идут по
одной ветке среза. Задача существует как родитель среза и источник контекста; собственной
готовности к ТЗ у неё нет, потому что ТЗ на задачу целиком не пишется.

<!-- example:start -->
Решение о поставке принято 2026-08-17.
<!-- example:end -->

ID среза вида `<ID задачи>-S<N>`. Дан ID задачи без номера среза - триаж прогоняется по
всем её срезам и отдаётся списком, по строке на срез.

## Как вызывается

Внутри циклового прогона: единица прогона - задача, `meeseeks-spec-cycle` диспатчит на
каждый срез задачи отдельного сабагента, и тот выполняет сначала `meeseeks-triage`, затем
`meeseeks-spec`. Вердикт триажа определяет, дойдёт ли срез до ТЗ в этом прогоне.

Прямой вызов человеком по ID среза остаётся как есть: тот же вход, тот же отчёт.

## Источник данных

Единственный источник - файл проекта в Google Drive (живая таблица, не статичный слепок).

<!-- example:start -->
```
fileId = "1mgoml4Kv3NPSoZYbbjTht0Fsw1Q_4xB1I9qDZ4N6zQg"
```
<!-- example:end -->

Не искать файл по имени и не полагаться на `project_knowledge_search` для этого шага - там
текст нарезан на чанки и не даёт точного попадания в строку по ID. Только прямое скачивание
и разбор таблицы.

## Шаг 1 - Получить ID среза

Если пользователь не назвал ID явно - взять последний упомянутый ID из истории разговора.
Если ID не находится нигде - спросить один раз, не гадать. Похожий ID не подбирать: ID,
различающиеся одним знаком в номере среза, - разные срезы.

<!-- example:start -->
`CI-9-S1` и `CI-9-S10` - разные срезы.
<!-- example:end -->

## Шаг 2 - Выгрузить и разобрать файл проекта

Скачать файл проекта прямой выгрузкой в xlsx и разобрать таблицу `openpyxl` с
`data_only=True`.

```python

#     fileId="1mgoml4Kv3NPSoZYbbjTht0Fsw1Q_4xB1I9qDZ4N6zQg",
#     exportMimeType="application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"
# )
# -> сохранить base64 в /home/Codex/project.xlsx, открыть openpyxl(data_only=True)
```

Листы: «Срезы», «Задачи», «Решения», «Развилки», «Открытые вопросы», «ADR», «Контракты».
Лист «Тесткейсы» нужен только для счётчика кейсов среза; разбор содержания кейсов - см.
`meeseeks-testcases`.

Лист «Подзадачи» источником не является: роль подзадачи - см. `meeseeks-decompose`.
Читать её можно как контекст, в вердикт она не входит.

## Шаг 3 - Найти срез

- Точное совпадение ID в колонке `ID` листа «Срезы».
- Строка задачи-родителя по колонке `Родитель` на листе «Задачи». Задачи с составными ID
  ищутся там же.
- Соседние срезы той же задачи - строки с тем же значением `Родитель`.
- Если ID не найден - сообщить прямо, похожий не угадывать.

<!-- example:start -->
Составной ID задачи: `DP-2-NM-6`.
<!-- example:end -->

Строка среза несёт `Результат` (что умеет фабрика после мержа) и `Критерий готовности`
(условие приёмки). Это и есть предмет триажа; пересказывать задачу вместо среза не нужно.

## Шаг 4 - Проверка готовности (ключевая часть скила)

Три независимых условия и дополнительные основания блокировки. Все обязательны.

**Условие 1 - зависимости разложены.** Колонка `Зависит от` содержит ID срезов через
запятую; прочерк `—` означает корень. Зависимость от среза той же задачи блокером не
является: порядок между срезами задачи выражает план прогона, ТЗ зависимого среза
публикуется после того, как предыдущее прошло успешно. Названные срезы других задач не
проверяются - это зона ответственности оператора; их статусы называются в отчёте.

Жизненный цикл среза - см. `meeseeks-slice`. Статус ведёт человек; скил его читает и не
проставляет.

ID в `Зависит от`, которого нет на листе «Срезы», - не «закрыт по умолчанию», а отдельная
находка: реестр рассогласован, вердикт `НЕ ГОТОВ`.

**Условие 2 - развилок нет.** Развилки живут на отдельном листе «Развилки» (Р-N), а не на
листе «Решения»: «Решения» - четыре колонки коротких фиксаций, развилок там нет. Пройти по
листу «Развилки» и взять записи, относящиеся к этому срезу, к его задаче или к теме,
которую он затрагивает. Блокирует колонка «Статус»: развилка блокирует, пока её статус не
закрыт. Статус `принято моделью` легален и не блокирует.

<!-- example:start -->
Диапазон идентификаторов развилок в файле проекта - Р-1…Р-52.
<!-- example:end -->

### Условие 3 - прослеживаемость вверх не разорвана

Первые два условия смотрят вниз - готов ли срез к ТЗ. Третье смотрит вверх: на чём срез
вообще стоит. Проверяется задача-родитель среза: собственного основания у среза нет, он
наследует основание задачи.

- У задачи-родителя заполнена колонка «Корень», и её значение разрешается: строка с этим
  ID существует на листе «Инициативы».
- Заполнена хотя бы одна из рамок задачи - «Рамка поведения» или «Рамка устройства».
- Колонка «Класс» сверяется с вычислением, а не берётся на веру. Правило корня и правило
  вычисления класса - см. `meeseeks-backlog`.

Любой из случаев ниже - разрыв прослеживаемости:

- «Корень» у задачи пуст;
- «Корень» не разрешается: строки с таким ID на листе «Инициативы» нет;
- обе рамки пусты;
- записанный «Класс» расходится с вычисленным.

Разрыв прослеживаемости даёт вердикт `НЕ ГОТОВ` и возвращает срез человеку. В отчёте он
называется отдельно от зависимостей и развилок и с ними не смешивается: закрывается он не
здесь, а заведением задачи по правилам `meeseeks-backlog`.

### Дополнительные основания блокировки

Сверх трёх условий вердикт `НЕ ГОТОВ` дают:

- **Открытый вопрос.** На листе «Открытые вопросы» есть ОВ-N со статусом `открыт` или
  `частично закрыт`, относящийся к уровню проекта, к рамке среза или к его задаче. Открытый
  ОВ - легальное основание не резать, а не повод домысливать ответ.
- **Рамка без приведённой декомпозиции.** Рамка устройства задачи стоит на листе «ADR» в
  состоянии `принят, декомпозиция не приведена`: реестры ниже ей противоречат.
- **Контракт без снимка.** В колонке «Контракт» среза стоит ID контракта, а у этой записи на
  листе «Контракты» пуста колонка «Где лежит снимок»: расхождение ловить нечем.

Каждое из оснований называется в отчёте отдельно и с зависимостями, развилками и разрывом
прослеживаемости не смешивается.

### Вердикт

- **ГОТОВ** - реестр зависимостей согласован, открытых развилок по срезу не найдено,
  прослеживаемость вверх не разорвана, дополнительных оснований блокировки нет.
- **НЕ ГОТОВ** - перечислить, что именно не закрыто, без домысливания вариантов решения
  (это не задача этого скила).

Статус самого среза вердикта не меняет, но называется в отчёте. Значения статусов и
жизненный цикл среза - см. `meeseeks-slice`. Если ТЗ по срезу уже написано, повторный
`meeseeks-spec` перезапишет существующее.

## Шаг 5 - Отчёт

Компактно, в чат (не файл):

```
[ID среза] - [репозиторий] : [базовая ветка] - [статус] - контракт: [ID контракта / прочерк]
Задача: [ID задачи] · [единица бэклога, одной строкой]
Результат: [1-2 предложения из колонки «Результат»]
Замыкающий: да / нет

План изменений (верхний уровень, по критерию готовности):
- [что меняется] - [где наблюдается]
- ...

Зависимости: [ID - статус - в задаче / внешняя] · [...]
Соседние срезы задачи: [ID - статус] (их предмет - out of scope этого ТЗ)
Тест-кейсов привязано: N [+ M кейсов задачи, если срез замыкающий]

Готовность к ТЗ: ГОТОВ / НЕ ГОТОВ
[если не готов - что закрыть перед meeseeks-spec]
```

Репозиторий и базовая ветка берутся из одной колонки «Репозиторий» листа «Срезы»: она несёт
и то, и другое. Базовая ветка не названа - это находка, а не повод подставить дефолтную
ветку репозитория. Контракт берётся из колонки «Контракт» строки среза: ID или прочерк.

Триаж по всей задаче (дан ID без номера среза) - тот же отчёт по строке на срез, плюс
порядок мержа по колонке `Зависит от` и указание замыкающего.

## Важно

- Это ориентировочный шаг, не источник истины для скила ТЗ. `meeseeks-spec` обязан сам
  заново читать файл проекта и код - не доверять этому отчёту как факту.
- Не читает код репозитория - только файл проекта.
- Не предлагает варианты решения развилок - только фиксирует, что они есть.
- Не проставляет статусы и в файл проекта не пишет.
- Предмет триажа - срез. Критерии готовности соседних срезов той же задачи в вердикт не
  входят: они закрываются своими PR.
