# Meeseeks Batch Slice — пакетная нарезка бэклога на срезы

## Место в методологии

Обёртка над `meeseeks-slice`, не замена ему. Правило границы среза, требование «один срез
— один репозиторий», перестановка «Источника» тест-кейсов, формат строки листа «Срезы» и
правило остановки на развилке живут в `meeseeks-slice` и здесь не дублируются. Этот скил
отвечает за три вещи: выборку и порядок задач, диспатч сабагентов, сведение результатов в
один патч.

Дальше по конвейеру: `meeseeks-spec` по каждому срезу отдельно.

**Граница скила:** в файл проекта не пишет, в Google Drive не пишет. Патч применяет
человек.

## Режим запуска

Cowork. Оркестратор — Fable 5, сабагенты — Opus 5.

Сабагент запускается инструментом Agent с параметром модели. Если параметр модели
недоступен и сабагент унаследует модель оркестратора — **стоп**: сообщить человеку и не
запускать прогон.

Рабочая папка прогона — `run/` в папке проекта: `run/plan.json`, `run/state.json`,
`run/tasks/<ID>.json`. Она же даёт возобновляемость: прогон, прерванный на середине,
продолжается с непройденных задач, уже полученные результаты сабагентов не
перезапрашиваются.

## Шаг 0 — Сверка файла проекта (блокирующий)

Сабагенты читают локальную копию файла проекта из папки проекта: по MCP её выгружал бы
каждый из трёх десятков, и каждый получил бы свой снимок. Локальная копия обязана
совпадать с оригиналом до начала работы.

1. `get_file_metadata` по `fileId` файла проекта — зафиксировать `modifiedTime`.
   <!-- example:start -->
   `fileId = 1mgoml4Kv3NPSoZYbbjTht0Fsw1Q_4xB1I9qDZ4N6zQg`
   <!-- example:end -->
2. `download_file_content` с `exportMimeType` = xlsx. Распаковка двухуровневая:

```python
inner = json.loads(result[0]["text"])
data = base64.b64decode(inner["content"])
```

3. Сравнить нормализованный дамп ячеек локальной копии и выгрузки по листам «Задачи»,
   «Подзадачи», «Тесткейсы», «Срезы», «Решения», «Развилки», «Открытые вопросы», «ADR»,
   «Репозитории». Байтовое сравнение не работает: экспорт Google Sheets в xlsx не
   байт-стабилен. У листа «Подзадачи» шапка стоит в третьей строке, строки 1-2 пустые:
   дамп снимается от найденной шапки, иначе сравнивается мусор.

Расхождение — **стоп**. Показать список расхождений, назвать `modifiedTime` оригинала,
спросить, обновить ли локальную копию. Ни одного сабагента до совпадения не запускать.

**Локальная копия обязана быть выгрузкой из Drive как есть.** Колонка «Фаза» листа
«Задачи» — формула; openpyxl при сохранении кэшированные значения формул не переносит, и
копия, прошедшая через openpyxl, теряет колонку целиком. Обновлять записью байтов
выгрузки, не пересохранением.

Листа «Срезы» в файле может ещё не быть — он заводится применением первого патча.
Отсутствие листа сверку не проваливает.

## Шаг 1 — Выборка и порядок

Выборка: строки листа «Задачи», где «Статус» = `ToDo`. Литерал матчится как есть.

**Фильтр готовности.** Задача берётся в прогон, только если у неё есть строки на листе
«Подзадачи» («Родитель» = ID) и строки на листе «Тесткейсы» («Единица бэклога» = ID).
Шапка листа «Подзадачи» стоит в третьей строке, строки 1-2 пустые: колонки читаются от
неё. Чтение от первой строки даёт пустоту, и фильтр отсеивает все задачи подряд.
Задача без подзадач возвращается в `meeseeks-decompose`, без кейсов — в
`meeseeks-testcases`; в прогон она не попадает и называется в отчёте отдельной строкой.

Порядок: слои DAG по колонке «Зависит от», рёбра только внутри выборки. Зависимость на
задачу вне выборки на порядок не влияет. Порядок нужен потому, что срез может зависеть от
среза блокирующей задачи: пока та не нарезана, ссылаться не на что.

Цикл в DAG — дефект данных: назвать его человеку и обработать остаток одним слоем
последовательно.

Внутри слоя — параллельно, по умолчанию не больше трёх сабагентов сразу.

Показать план до запуска: сколько задач, какие слои, сколько отсеяно фильтром готовности.
Подтверждение не требуется, но план виден.

## Шаг 2 — Диспатч

На каждую задачу слоя — отдельный сабагент со скилом `meeseeks-slice`. В промпт
подставляются: `task_id`, `project_file` (локальная копия), `output_path` =
`run/tasks/<ID>.json`, `resolutions` (пусто на первом заходе).

Сабагент возвращает JSON: `verdict`, `slices` (строки листа «Срезы»), `testcase_moves`
(TC-ID и новое значение «Источник»), `forks`, `estimate` (оценка каждого среза в проходах
агента), `note`.

Оркестратор в нарезку не вмешивается: сам не группирует, репозитории за сабагента не
определяет, код за него не читает. Его дело — вход, выход и развилки.

## Шаг 3 — Разбор возврата

| `verdict` | Действие |
|---|---|
| `sliced` | Срезы и перестановки кейсов в `run/state.json`, задача закрыта |
| `forks` | Шаг 4 |
| `oversized` | Парковка: предложенный сабагентом разрез на задачи отдаётся человеку |
| `exists` | Парковка: нарезка уже есть, патч по задаче не выпускается |
| `conflict` | Парковка: существующая нарезка противоречит декомпозиции |
| `not_ready` | Парковка: вход к нарезке не готов (см. `meeseeks-slice`) |

Схема невалидна или файла нет — один повторный диспатч той же задачи. Второй сбой —
парковка с пометкой «сабагент не вернул результат».

## Шаг 4 — Развилка: проверка основания, затем остановка

**Сначала проверка, закрыта ли развилка уже.** Закрыть — значит найти существующее
основание, а не выбрать более удачный вариант. Допустимые основания, в порядке проверки:

1. Строка листа «Решения», прямо закрывающая этот выбор.
2. Строка листа «Развилки», закрывающая этот же выбор. Статус `принято моделью` —
   основание наравне с остальными.
3. Строка листа «ADR» локальной копии: развилка закрыта, если «Что этим запрещено»
   отсекает вариант. ADR ведутся строками листа, а не файлами в папке проекта и не в
   `docs/` репозитория: по старым адресам искать нечего.
4. Однозначный факт кода: вариант описывает механизм, которого нет, либо противоречит
   существующему контракту. Читается через MCP того хостинга, который назван в реестре
   «Репозитории».
   <!-- example:start -->
   Реестр указывает на GitLab — читать через GitLab MCP; на GitHub — через GitHub MCP.
   <!-- example:end -->
5. Решение, принятое человеком внутри этого же прогона по другой задаче.

Журнал разделён на два листа, и проверяются оба: «Решения» несёт короткие фиксации,
«Развилки» — разобранный выбор с вариантами и отвергнутым.

Отдельная проверка — лист «Открытые вопросы». Развилка, упирающаяся в открытый ОВ,
основанием не закрывается и человеку как выбор не предъявляется: открытый ОВ есть
легальное основание не резать и остановиться. Задача паркуется со ссылкой на ОВ-N.

Основание найдено — развилка закрыта ссылкой, задача уходит на повторный диспатч (Шаг 5).
Запись в `state.decisions`: дата прогона, формулировка, варианты, принятый вариант,
отвергнутое, обоснование с указанием источника (дата строки «Решения», ID строки
«Развилки», ID строки «ADR», путь к файлу кода), статус `принято моделью`. Основание,
которое нельзя назвать ссылкой, — не основание.

**Основания нет — прогон останавливается.** Уже запущенные сабагенты текущего слоя
дорабатывают; новые не запускаются. Развилки предъявляются человеку по одной задаче:

```
[ID] — [первая строка «Единицы бэклога»]

## Развилка 1: [суть]
Контекст: [факты кода и реестров]
Что уже проверено: [какие решения, ADR и файлы смотрели и почему не закрылось]

Вариант А: [описание]
  + [плюсы]
  − [риски]
Вариант Б: […]
```

«Что уже проверено» — обязательная строка: она отделяет развилку, у которой основания
нет, от развилки, основание которой оркестратор не нашёл.

Ответ человека попадает в `state.decisions` тем же форматом, статус — `принято`. Дальше — Шаг 5, затем прогон
продолжается с прерванного места: остаток текущего слоя, потом следующие слои.

Человек может ответить «пропустить» — задача остаётся припаркованной, прогон продолжается.
Припарковка зависящие задачи не блокирует: у них развилок может и не оказаться.

## Шаг 5 — Повторный диспатч

Тот же промпт сабагента, `resolutions` заполнен: формулировка развилки, принятый вариант,
источник. На задачу приходится не больше двух диспатчей на раунд закрытия развилок.
Сабагент вернул `forks` снова — парковка, новые развилки идут человеку вместе со старыми.

## Шаг 6 — Сводный патч

Один файл на прогон, три листа:

- **«Развилки»** — все решения прогона: закрытые оркестратором по основанию и принятые
  человеком. Двенадцать колонок листа (`ID | Дата | Уровень | Развилка | Контекст |
  Варианты | Принято | Обоснование | Последствия | Что отвергнуто и почему | Основание |
  Статус`) + `Статус строки` = `добавлено`, заливка зелёная `C6EFCE`. На лист «Решения»
  прогон не пишет: там четыре колонки коротких фиксаций, вариантов и отвергнутого они не
  несут.
- **«Срезы»** — все новые строки прогона, в порядке слоёв DAG и нумерации `S<N>`. Девять
  колонок листа (`ID | Родитель | Репозиторий | Результат | Критерий готовности | Зависит
  от | Замыкающий | Статус | Контракт`) + `Статус строки` = `добавлено`, заливка зелёная.
  «Контракт» — ID контракта или прочерк. Значение «Репозитория» переносится из возврата
  сабагента как есть, вместе с базовой веткой среза.
- **«Тесткейсы»** — строки с переставленным «Источником», выпускаются целиком. Девять
  колонок листа (`TC-ID | Уровень | Тип | Единица бэклога | Источник | Given | When |
  Then | Контракт`) + `Статус строки` = `изменено`, заливка жёлтая `FFEB9C`. Строка идёт
  целиком, поэтому «Контракт» переносится из существующей строки как есть: пустотой его
  не затирать.

Лист «Задачи» патч не трогает: статус задачи остаётся `ToDo`, состояние работы несёт
колонка «Статус» листа «Срезы» со значением `NeedSpec`.

Припаркованные задачи ни в один лист не попадают: следующий прогон возьмёт их снова.

Имя файла ASCII — карточка `present_files` не отрисовывается для кириллицы в имени:
`batch-slice-patch.xlsx`, в `/mnt/user-data/outputs/`.

## Критические правила

- Расхождение локальной копии с Drive — стоп до запуска сабагентов, всегда.
- Литерал статуса `ToDo` матчится как есть.
- Задача без подзадач или без кейсов в прогон не берётся: нарезать нечего.
- Сабагент — Opus, оркестратор — Fable. Не подтверждается модель сабагента — прогон не
  запускается.
- Оркестратор закрывает развилку только ссылкой на существующее основание. Основания нет
  — прогон останавливается и ждёт человека, выбор за него не делается.
- Оркестратор не группирует сам, даже последнюю оставшуюся задачу, даже если она выглядит
  простой.
- Частичная нарезка не выпускается: осталась незакрытая развилка — задача припаркована
  целиком.
- Патч один на прогон. Отдельные файлы по задачам не выпускаются.
- В файл проекта и в Google Drive скил не пишет.
