# Meeseeks Batch Decompose — пакетная декомпозиция бэклога

## Место в методологии

Обёртка над `meeseeks-decompose`, не замена ему. Правила разреза, словарь слоёв, форма
критерия готовности и правило остановки на развилке живут в `meeseeks-decompose` и
здесь не дублируются. Этот скил отвечает за три вещи: выборку и порядок задач, диспатч
сабагентов, сведение результатов в один патч.

Дальше по конвейеру: `meeseeks-testcases` → `meeseeks-slice` → `meeseeks-spec`.

**Граница скила:** в файл проекта не пишет, в Google Drive не пишет. Патч применяет
человек.

## Режим запуска

Cowork. Оркестратор — Fable 5, сабагенты — Opus 5.

Сабагент запускается инструментом Agent с параметром модели; промпт — содержимое
`agents/decomposer.md` с подставленными параметрами. Если параметр модели у инструмента
недоступен и сабагент унаследует модель оркестратора — **стоп**: сообщить человеку и не
запускать прогон. Двадцать с лишним задач на неверной модели — не та ошибка, которую
исправляют после.

Рабочая папка прогона — `run/` в папке проекта: `run/plan.json`, `run/state.json`,
`run/tasks/<ID>.json`. Она же даёт возобновляемость: прогон, прерванный на середине,
продолжается с непройденных задач, уже полученные результаты сабагентов не
перезапрашиваются.

## Шаг 0 — Сверка файла проекта (блокирующий)

Сабагенты читают локальную копию файла проекта из папки проекта — по MCP её выгружал
бы каждый из двадцати с лишним, и каждый получил бы свой снимок. Значит локальная копия
обязана совпадать с оригиналом до начала работы.

1. `get_file_metadata` по `fileId` файла проекта — зафиксировать `modifiedTime`.
   <!-- example:start -->
   `fileId = "1mgoml4Kv3NPSoZYbbjTht0Fsw1Q_4xB1I9qDZ4N6zQg"`
   <!-- example:end -->
2. `download_file_content` с `exportMimeType` = xlsx. Распаковка двухуровневая:

```python
inner = json.loads(result[0]["text"])
data = base64.b64decode(inner["content"])
```

3. Сверка по листам, которые читает декомпозиция:

```
python scripts/check_sync.py --local <копия в папке проекта> --drive <выгрузка> \
    --sheets "Задачи,Подзадачи,Решения,Развилки,Открытые вопросы,ADR,Контракты"
```

Набор листов задан тем, что читает декомпозиция и из чего закрываются развилки: сами
задачи и подзадачи, оба журнала («Решения» и «Развилки»), реестр открытых вопросов и
оба реестра рамок и границ — «ADR» и «Контракты». Лист, по которому идёт закрытие
развилки, но который не сверен, даёт прогон по устаревшему снимку рамок.

Код возврата 1 — **стоп**. Показать человеку список расхождений, назвать
`modifiedTime` оригинала и спросить, обновить ли локальную копию. Ни одного сабагента
до совпадения не запускать: расхождение означает, что декомпозиция пойдёт по
устаревшему тексту задач, и результат придётся выбросить целиком.

Байтовое сравнение здесь не работает — экспорт Google Sheets в xlsx не байт-стабилен.
Скрипт сравнивает нормализованный дамп ячеек.

**Локальная копия обязана быть выгрузкой из Drive как есть.** Локальную копию
обновлять записью байтов выгрузки, не пересохранением: openpyxl при сохранении
кэшированные значения формул не переносит, и колонки-формулы в копии теряются.

## Шаг 1 — Выборка и порядок

```
python scripts/select_tasks.py <project.xlsx> --out run/plan.json
```

Статус матчится литералом файла проекта: `Не декоспозирована`, с опечаткой. Опечатка —
факт данных, а не ошибка скила; исправление литерала в таблице потребует правки и
здесь.

Скрипт строит слои DAG по колонке «Зависит от», рёбра — только внутри выборки.
Зависимость на задачу вне выборки означает, что та уже декомпозирована либо не в
скоупе, и на порядок не влияет.

Порядок нужен потому, что связанные задачи снимают развилки друг друга: цепочка
зависимых задач при одновременной раздаче даст на каждой следующей задаче развилку,
которую закрыла бы предыдущая.
<!-- example:start -->
Цепочка `IC-1 → IC-2 → …`.
<!-- example:end -->
Прогон идёт слоями, внутри слоя — параллельно, по умолчанию не больше трёх сабагентов
сразу.

Цикл в DAG скрипт помечает `"cycle": true` и кладёт остаток одним слоем. Это дефект
данных: назвать его человеку и продолжить, обрабатывая остаток последовательно.

Показать человеку план до запуска: сколько задач, какие слои, сколько сабагентов
ожидается. Подтверждение не требуется, но план виден.

## Шаг 2 — Диспатч

На каждую задачу слоя — отдельный сабагент. В промпт подставляются: `task_id`,
`project_file`, `output_path` = `run/tasks/<ID>.json`, `resolutions` (пусто на первом
заходе).

Оркестратор в декомпозицию не вмешивается, код за сабагента не читает, швы за него не
ищет. Его дело — вход, выход и развилки.

## Шаг 3 — Разбор возврата

По `verdict` из `run/tasks/<ID>.json`:

| `verdict` | Действие |
|---|---|
| `decomposed` | Подзадачи в `run/state.json`, задача закрыта |
| `forks` | Шаг 4 |
| `not_needed` | Парковка: вердикт «декомпозиция не требуется» — суждение, а не патч |
| `oversized` | Парковка: предложенный разрез на задачи отдаётся человеку |
| `conflict` | Парковка: расхождение нарезки с кодом отдаётся человеку |

Схема невалидна или файла нет — один повторный диспатч той же задачи. Второй сбой —
парковка с пометкой «сабагент не вернул результат».

## Шаг 4 — Закрытие развилок оркестратором

Оркестратор пробует закрыть развилку сам. **Закрыть — значит найти уже существующее
основание, а не выбрать более удачный вариант.** Допустимые основания, в порядке
проверки:

1. Строка листа «Решения», прямо закрывающая этот выбор.
2. Строка листа «Развилки» (Р-N), где тот же выбор уже закрыт: поля «Принято» и «Что
   отвергнуто и почему». Статус `принято моделью` закрытию не мешает.
3. Строка листа «ADR», поле «Что этим запрещено», запрещающее один из вариантов.
   Критерий связывания рамки с развилкой: существует правдоподобная реализация
   варианта, нарушающая хотя бы один пункт «Что этим запрещено». Совпадение термина,
   репозитория или задачи связыванием не считается.
4. Однозначный факт кода: вариант описывает механизм, которого в коде нет, либо
   противоречит существующему контракту. Код читается через MCP того хостинга, который
   назван в реестре «Репозитории».
5. Решение, принятое человеком внутри этого же прогона по другой задаче.

Открытый вопрос листа «Открытые вопросы» (ОВ-N), покрывающий эту развилку, — основание
не закрывать её вовсе: задача паркуется со ссылкой на ОВ, человеку развилка
предъявляется как уже поставленный вопрос. Это штатный исход, а не ненайденное
основание.

Ни одно основание не найдено — развилка идёт человеку. Правдоподобие, симметрия с
соседней задачей, «очевидность» варианта и предпочтение оркестратора основаниями не
являются. Запрет `meeseeks-decompose` на выбор за человека этим скилом не ослабляется:
переносится право сослаться на уже принятое решение, не право принять новое.

Каждая закрытая развилка записывается в `state.forks` строкой листа «Развилки»: ID,
дата прогона, уровень, формулировка развилки, контекст, варианты, принятый вариант,
обоснование, последствия, что отвергнуто и почему, основание, статус. Основание —
ссылка на источник закрытия: номер строки «Решения», ID развилки Р-N, ID рамки ADR-N,
путь к файлу кода. Статус — `принято моделью` для закрытых оркестратором по основанию.
Лист «Решения» для этого не годится: четыре колонки, вариантов и отвергнутого он не
держит. Основание, которое нельзя назвать ссылкой, — не основание.

Все развилки задачи закрыты — повторный диспатч (Шаг 5). Осталась хоть одна —
парковка целиком: частичная декомпозиция не выпускается.

## Шаг 5 — Повторный диспатч

Тот же сабагент-промпт, `resolutions` заполнен: формулировка развилки, принятый
вариант, источник. На задачу приходится не больше двух диспатчей на раунд закрытия
развилок. Если после подстановки решений сабагент возвращает `forks` снова — парковка,
новые развилки идут человеку вместе со старыми.

## Шаг 6 — Вопрос человеку

Задаётся после того, как отработал текущий слой, не в момент возникновения. Слой
доходит до конца, дальше припаркованные задачи слоя предъявляются **по одной**: одна
задача — все её незакрытые развилки — ответ — следующая задача.

Формат по задаче:

```
[ID] — [первая строка «Единицы бэклога»]

## Развилка 1: [суть]
Контекст: [факты кода и бэклога]
Что уже проверено: [почему не закрылось само — какие решения и файлы смотрели]

Вариант А: [описание]
  + [плюсы]
  − [риски]
Вариант Б: […]
```

«Что уже проверено» — обязательная строка: она отделяет развилку, у которой основания
нет, от развилки, основание которой оркестратор не нашёл.

Ответ человека попадает в `state.forks` тем же форматом, что и самостоятельно закрытая
развилка, с обоснованием из его формулировки и статусом `подтверждено человеком`.
Дальше — Шаг 5.

Человек может ответить «пропустить» — задача остаётся припаркованной и в патч не
входит.

Следующий слой начинается после того, как припаркованные задачи текущего разобраны.
Задача, оставшаяся припаркованной, зависящие от неё задачи не блокирует: они идут
своим чередом, развилок у них может и не оказаться.

## Шаг 7 — Сводный патч

```
python scripts/build_patch.py --state run/state.json --source <project.xlsx> \
    --out /mnt/user-data/outputs/batch-decompose-patch.xlsx
```

Три листа:

- **«Развилки»** — все развилки прогона: закрытые оркестратором по основанию и
  закрытые ответом человека. Строки новые, заливка зелёная `C6EFCE`.
- **«Задачи»** — только успешно декомпозированные, колонка «Статус» = `ToDo`
  (`ToDo` у задачи означает декомпозированную задачу). Строки изменённые, заливка
  жёлтая `FFEB9C`. Строка переносится из файла проекта всеми двенадцатью колонками:
  изменённая строка применяется целиком, и пропущенная колонка затрёт корень, рамки,
  класс или контракт пустотой.
- **«Подзадачи»** — все новые строки прогона, в порядке слоёв DAG и нумерации.
  Заливка зелёная.

Припаркованные задачи ни в один лист не попадают: их статус остаётся
`Не декоспозирована`, и следующий прогон возьмёт их снова.

Имя файла ASCII — карточка `present_files` не отрисовывается для кириллицы в имени.

## Критические правила

- Расхождение локальной копии с Drive — стоп до запуска сабагентов, всегда.
- Литерал статуса матчится как есть, включая опечатку.
- Сабагент — Opus, оркестратор — Fable. Не подтверждается модель сабагента — прогон
  не запускается.
- Оркестратор закрывает развилку только ссылкой на существующее основание. Выбор
  между вариантами без основания — человеку.
- Частичная декомпозиция не выпускается: осталась незакрытая развилка — задача
  припаркована целиком.
- Оркестратор не декомпозирует сам, даже последнюю оставшуюся задачу, даже если она
  выглядит простой.
- Патч один на прогон. Отдельные файлы по задачам не выпускаются.
- В файл проекта и в Google Drive скил не пишет.
