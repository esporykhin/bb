# Фабрика софта

Плагин хранит проекты и полный версионируемый пакет Mr Meeseeks. Пакет не инжектируется автоматически в каждый агентский тред.

Команды:

- `bb meeseeks-factory projects list [--limit 1..20] [--offset 0..500]` — страница карточек.
- `bb meeseeks-factory projects discover [--query text] [--limit 1..20] [--offset 0..1000000]` — поиск каталогов в `~/Desktop/Проекты разработка` на сервере BB, без чтения файлов проектов.
- `bb meeseeks-factory projects show <id>` — исходное состояние и закреплённая ревизия проекта.
- `bb meeseeks-factory projects create '<JSON>'` — новая карточка.
- `bb meeseeks-factory methodology info` — текущая версия пакета.

JSON карточки: `{"name":"Продукт","mode":"existing","repository":"/path/to/repo","baseline":"Работает API; тесты в tests/; документация в docs/"}`. Для нового продукта mode=`new`, repository и baseline допускают пустую строку.

По умолчанию существующий продукт выбирается из каталога Desktop/Проекты разработка; список поддерживает корень-symlink, поиск и страницы. Можно явно выбрать ручной ввод пути/URL. Discovery читает только непосредственные каталоги и метаданные ссылок, не создаёт карточки автоматически и не обращается к удалённым хостам.

Вход существующего продукта требует ручной записи исходного состояния. Это не результат автоматического аудита кода. Запуск агентов и upstream sync пока отсутствуют. Просмотр и редактор файлов доступны на странице «Фабрика софта» в BB. Сохранение создаёт новую ревизию; версия проекта меняется только явным переключением в карточке.

Нельзя сообщать о доставленном результате только по статусу adoption: это ручная отметка пользователя. Полный цикл методологии описан в docs/factory/README.md; реализованные возможности перечислены в корневом README.

## История записей

В рабочем пространстве выберите запись и откройте «История изменений»: снимки версий, их поля, связи, статус и даты доступны только для чтения. Просмотр не восстанавливает и не перезаписывает текущую запись. Для записей без прежней истории исходное состояние фиксируется при первой следующей правке.

Удаление проекта с активными записями запрещено. Для пустого проекта отдельное подтверждение удаления карточки явно включает удаление сохранённой истории; репозиторий не удаляется.

## Первичный разбор проекта

В рабочем пространстве проекта есть «Начать разбор проекта». Кнопка создаёт обычную задачу агента BB для локального репозитория и закреплённой версии инструкций; просмотр карточки сам по себе запуск не создаёт. В карточке нужен абсолютный путь к существующему локальному каталогу. URL без checkout не подходит.

Панель показывает состояние и ссылку на задачу, затем ссылки на импортированные черновики. Черновики требуют источников и не перезаписывают прежние записи. При неизвестном состоянии существующий запуск нужно проверить; автоматический повтор не выполняется. Первичный разбор не равен запуску полного delivery cycle.

Если задача агента остановилась без импорта, панель показывает необходимость внимания, а не готовность. Продолжите задачу в чате или явно закройте запуск без результата; сервер проверяет отсутствие выполняющейся задачи. После сетевой неопределённости интерфейс сверяет requestId и принимает уже существующий запуск. Повторный запрос автоматически не отправляется.

## Нативная работа с агентом

Откройте проект из обзора, начните первичный разбор и продолжайте разговор в обычном треде BB. Основная кнопка рабочего пространства переводит в тот же тред. Фабрика показывает свою нативную карточку контекста только для связанных тредов; в режиме banner доступна компактная ссылка. Нажатие открывает именно связанный проект фабрики. Формы остаются средством просмотра и правок, а не обязательным началом работы.

Если после потери ответа запуск пока не найден, сохраняйте исходный requestId. Повтор возможен только тем же запросом; идентификатор хранится в sessionStorage отдельно для каждого проекта до отправки RPC. Отсутствие записи не разрешает автоматически создать новый UUID.
