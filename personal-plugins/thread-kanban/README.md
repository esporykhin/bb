# Thread Kanban

Канбан тредов BB: постановка задач агентам, фильтры по проекту и ответственному,
поиск, перетаскивание карточек и статусы выполнения.

## Использование

Откройте **Thread Kanban** в навигации или **Kanban** в панели треда.
Кнопка **Новая задача** открывает форму: проект, агент, название и описание.
**Создать и запустить** создаёт обычный BB-тред и сразу начинает выполнение.
Ссылка в уведомлении открывает созданный тред; доска остаётся на месте.
Фильтр **Все агенты** показывает задачи выбранного ответственного.

Новый тред получает полные инструкции выбранного профиля. Короткие инструкции
передаются также через SDK configure; для длинных есть инструмент
`kanban_role_context`, который агент должен читать при начале сессии.
Профиль — инструкции роли: модель, провайдер и разрешения берутся из настроек
проекта BB. Это не полная копия нативного Codex subagent или его sandbox.

**Ответственный** на существующей карточке — учётная метка, её смена не меняет
роль работающей сессии. Для выполнения другой ролью создайте новую задачу.

## Установка

```sh
npm install --include=dev
bb plugin build
bb plugin install . --yes
```

Требования: BB SDK 0.6.104, Node 22+, Python 3.11+ для импорта ролей.

## Импорт ролей

```sh
python3 scripts/import-codex-profiles.py --output /tmp/kanban-profiles.json
bb plugin rpc call thread-kanban profiles_import --input-file /tmp/kanban-profiles.json
rm /tmp/kanban-profiles.json
```

Файл экспорта создаётся с правами 0600, не перезаписывает существующий файл.
Импорт включает явно настроенные роли из `~/.codex/config.toml` и автоматически
обнаруживаемые именованные роли из `~/.codex/agents/*.toml`; явные определения
имеют приоритет. Экспорт содержит только id, имя и инструкции. Модели,
разрешения, sandbox и настройки рассуждений не переносятся. Профили хранятся
в SQLite плагина, персональные инструкции не включаются в исходники.

## Команды

```sh
bb thread-kanban profiles
bb thread-kanban create <project-id> <agent-id> "Название" "Описание"
bb thread-kanban assign <thread-id> <agent-id>
bb thread-kanban move <thread-id> in_progress
bb thread-kanban move <thread-id> blocked
bb thread-kanban move <thread-id> review
bb thread-kanban move <thread-id> done
bb thread-kanban list
```

RPC: `board`, `profiles_list`, `profiles_import`, `createTask`, `assign`, `move`.
`createTask` принимает необязательный `requestId`: повтор с тем же содержимым
возвращает тот же тред. Для неопределённого результата сетевого вызова повторный
запуск блокируется, чтобы не продублировать работу. Проверьте список тредов
перед новым запросом. Изменение формы начинает новый запрос.

## Переходы и ограничения

- Начало хода → «В работе», кроме завершённых карточек.
- Конец хода → «На проверке», если карточка была в работе или без статуса.
- Ошибка → «Заблокировано», кроме завершённых карточек.
- «Завершено» выставляется явно пользователем или агентом.
- Архив скрывает карточку, удаление треда очищает статус, ответственного и запрос.

События во время отключения плагина не воспроизводятся. Такие сохранённые
статусы нужно исправить вручную. Треды без записи отображаются по текущему
состоянию выполнения или в бэклоге. Скрытые и архивные треды не показываются.
Обновления передаются realtime; после reconnect и возврата фокуса доска
перечитывает состояние.

## Проверки

```sh
npm test
npx tsc --noEmit
bb plugin build
```

Интеграционные тесты используют официальный fake host BB с реальной временной
SQLite. Они проверяют роли, создание, идемпотентность, ошибки, переходы,
изолированную конфигурацию агентов и удаление записей.
