# Устройство плагина

`server.ts` содержит схемы RPC, SQLite, CLI и lifecycle listeners.
`app.tsx` — страница и панель треда: форма задачи, фильтры, drag-and-drop,
подписи ответственных, select статуса и переход в тред.
`scripts/import-codex-profiles.py` — локальный экспорт инструкций ролей.
`skills/thread-kanban` — правила сопровождения карточек агентами.

## Роли

Trusted catalog профилей хранится в SQLite плагина. `createTask` проверяет
профиль и проект, передаёт `roleId`/`roleName` в pluginMetadata при spawn.
Полные инструкции включаются в начальное сообщение. Через `agents.configure`
тред получает указание применять роль и инструмент `kanban_role_context`.
Последний читает профиль только текущего треда по metadata этого плагина.
Длинные инструкции не обрезаются; configure остаётся в лимите SDK 4096.
Навык канбана включён и в обычные, и в ролевые треды.

Метка ответственного хранится отдельно от роли запуска. `assign` меняет
только метку: смена инструкций в уже работающей provider session не обещается.
Профили не задают модель, провайдера, sandbox или разрешения инструментов.

## Состояние и конкуренция

Статусы, ответственные, профили и ключи запросов хранятся в отдельных таблицах.
Синхронный upsert обновляет одну карточку, записи разных тредов не затираются.
Для одной карточки побеждает последняя запись. Realtime-сигнал инвалидирует
снимок на клиентах. UI отбрасывает устаревшие ответы и обновляется при reconnect.

`requestId` связывает нормализованный SHA-256 содержимого и созданный тред.
Повтор возвращает прежний результат; конкурентный запрос или неопределённый
исход не создаёт второй тред. До резервирования проверяется существование
проекта. Удаление треда очищает карточку, ответственного и связанные ключи.
Резервации с неизвестным результатом сохраняются для защиты от дубликатов.

Подписки и SQLite освобождает host SDK при выгрузке. События во время
отключения плагина не воспроизводятся; это ограничение описано в README.
