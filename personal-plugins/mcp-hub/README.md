# MCP Hub

Единый реестр внешних MCP-серверов для агентов BB. Плагин находится в личном форке и работает через общий механизм инструментов BB: Codex, Claude Code, Pi и адаптеры ACP с поддержкой инструментов получают один хаб.

## Использование

Откройте **MCP Hub** в боковой панели. Если пункт скрыт, найдите его через **More**. Добавьте сервер HTTP или stdio, сохраните и включите доступ агентам. «Проверить / инструменты» подключается к серверу и показывает схемы аргументов. Настройки редактируются обычными полями: переменные окружения — строками «имя / значение», аргументы запуска — отдельными строками с кнопками добавления и удаления. При повторном открытии формы загружаются сохранённые значения. Токены скрыты до нажатия «Показать»; их можно посмотреть, изменить или очистить.

Для установленного Kaiten есть отдельные поля адреса и API-токена. Адрес принимается как короткий поддомен, доменное имя или полный HTTP(S)-URL; ранее сохранённый URL в поле поддомена исправляется при сохранении. Команда запуска вынесена в дополнительные настройки. Отдельная кнопка проверки доступа выполняет только чтение пространств Kaiten; получение каталога инструментов само по себе не проверяет авторизацию.

Новые чаты получают `mcp_hub_search` и `mcp_hub_call`. Сначала агент находит инструмент и его JSON-схему, затем вызывает его по `serverId` и `name`. Добавление и изменение серверов не требует настройки каждого провайдера или перезагрузки плагина. Уже открытым сессиям, которые ещё не получили инструменты хаба, может понадобиться новый чат.

Включение сервера разрешает агентам его инструменты, в том числе изменяющие внешние данные. Хаб не добавляет отдельные согласования каждого upstream-вызова. Инструкции агента требуют действовать в рамках поручения пользователя; настройки провайдерного sandbox не изолируют процесс плагина.

## Команды

```sh
bb mcp-hub list
bb mcp-hub show analytics
bb mcp-hub add analytics --name "Аналитика" --url https://example.com/mcp --enabled
bb mcp-hub inspect analytics
bb mcp-hub search "sales" --server analytics --limit 10 --offset 0
bb mcp-hub call analytics tool_name --arguments '{"item":123}'
bb mcp-hub add local --transport stdio --command /absolute/path/to/server --args '[]' --enabled
bb mcp-hub remove local
```

Для передачи токена используйте `--token-stdin`, для stdio env — `--env-stdin`, для приватных аргументов инструмента — `--arguments-stdin`. Не вставляйте реальные секреты в командную строку. `add` также обновляет существующий сервер; `--enabled` явно разрешает вызовы, `--disabled` отключает их. Новый сервер без этих флагов сохраняется выключенным; при обновлении сохраняется прежнее состояние. Вызов с upstream `isError` завершает CLI с кодом 1. `show <id>` показывает настройки без значений секретов. Явный `--show-secrets` раскрывает токен и env для ручного просмотра; не используйте его в логах. `--help` описывает все опции.

## SDK

UI и CLI обращаются к одному сервису. SDK использует существующий `plugins.callRpc`; схемы опубликованы через discoverable RPC:

```ts
import { z } from "zod";
const result = await sdk.plugins.callRpc({
  pluginId: "mcp-hub",
  method: "list",
  input: null,
  outputSchema: z.object({ servers: z.array(z.unknown()) }),
});
```

Точная схема доступна через `bb plugin rpc inspect mcp-hub`. Методы: `list`, `configuration`, `upsert`, `remove`, `inspect`, `search`, `call`. Внутри плагина используется типизированный `rpcContract` из `src/contract.ts`.

## Транспорт и границы

Поддержаны Streamable HTTP с необязательным Bearer-токеном и stdio. Старый HTTP+SSE transport, OAuth, интерактивные elicitation, MCP resources и prompts не поддержаны. Через агентский мост передаются текст и изображения; неподдерживаемый контент обозначается явно. Автоматического повтора вызовов нет: после таймаута изменение на внешней стороне уже могло произойти.

**Stdio запускается на машине сервера BB**, а не на машине выбранного чата. Указывайте исполняемый файл, доступный именно там. Не передавайте секреты в аргументах команды: список показывает аргументы; используйте env. HTTP URL не должен содержать логин, пароль или query-параметры кроме `tools`.

Реестр с токенами и env хранится в штатной секретной настройке `registry` (файл с правами 0600); списки и диагностические ошибки не раскрывают токены и значения env. Явное открытие формы настроек вызывает `configuration` и возвращает сохранённые значения владельцу BB, чтобы их можно было увидеть и редактировать. Список показывает только наличие токена и имена переменных. Пустой реестр — исходное состояние: существующие настройки Codex/Claude автоматически не импортируются.

## Разработка

```sh
pnpm exec turbo run typecheck lint test build --filter=bb-plugin-mcp-hub
bb plugin install ./personal-plugins/mcp-hub
```

Плагин подключён к workspace и Turbo. Установка из локального пути сохраняет связь с checkout; после изменений выполните сборку и `bb plugin reload mcp-hub`. Перезапуск ядра или пересборка desktop-приложения не нужны.
